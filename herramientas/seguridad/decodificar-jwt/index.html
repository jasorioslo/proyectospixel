Decodificador de JWT

Inspecciona header, payload y fechas de un token JWT. Ideal para depurar autenticación (la firma no se verifica).

El token se decodifica localmente y nunca se envía. La verificación de firma no se realiza en el navegador.

Qué es un JWT y cómo se inspecciona

Un JWT (JSON Web Token) es un token con tres partes separadas por puntos: header.payload.signature, donde las dos primeras van en Base64URL. Transporta la identidad y los permisos en aplicaciones modernas.

Esta herramienta decodifica el header y el payload para que los leas, muestra las fechas (exp/iat/nbf) y avisa si ha expirado o si el algoritmo es «none». Eso sí: no verifica la firma (eso requiere la clave del servidor).

Cómo decodificar un JWT paso a paso

  1. Pega el token JWT completo (con sus dos puntos).
  2. Pulsa decodificar: verás el header, el payload y la firma.
  3. Revisa los avisos: si está expirado, si aún no es válido o si viene sin firma.

Casos de uso

  • Depurar autenticación: ver qué claims viajan en el token.
  • Comprobar expiración: evitar el clásico «token expired».
  • Seguridad: detectar tokens con algoritmos débiles o claims raros.
  • Aprendizaje: entender la estructura de los JWT.

Preguntas frecuentes

¿Verifica la firma?

No: verificarla exige la clave secreta o la pública del emisor. Aquí solo se inspecciona el contenido.

¿Es seguro pegar un token real?

El análisis es local, pero un JWT real da acceso mientras siga vigente: si es de producción, mejor usa uno de pruebas.

¿Qué significa «alg: none»?

Que el token no está firmado: es una señal de alarma en aplicaciones reales.

¿Qué son exp, iat y nbf?

Fechas estándar: expiración, emisión y «no válido antes de». Se muestran en UTC.
